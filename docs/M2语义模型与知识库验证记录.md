## 自动化验证

### 1. 知识资产一致性

```powershell
python -m unittest discover -s demo/enterprise-finance/knowledge -p 'test_*.py' -v
```

结果：`3/3` 通过。已确认 63 个语义字段全部存在于 `01_schema.sql`，5 个核心指标均有业务知识，18 条标准 SQL 均为单条只读查询。

### 2. 标准 SQL 真实执行

逐条读取 `标准问答.json`，通过 `enterprise-finance-mysql-1` 中的 MySQL 8.4 执行。

结果：`18/18` 执行成功，无语法错误或缺失表字段。

### 3. 管理库和向量库导入

运行环境：后端 `http://127.0.0.1:8065`，Agent `5`，数据源 `4`。数据源连接测试和 13 张业务表 Schema 初始化均成功。

```powershell
python demo/enterprise-finance/knowledge/import_knowledge.py --agent-id 5 --wait-seconds 300
```

首次与第二次重复执行结果一致：

```json
{
  "semanticModels": 63,
  "businessKnowledge": 14,
  "standardQa": 18,
  "embeddedBusinessKnowledge": 14,
  "embeddedStandardQa": 18

```

重复导入后管理库仍为 `63/14/18`，无重复记录，失败向量数为 `0`。

### 4. 真实业务词召回

```powershell
python demo/enterprise-finance/knowledge/verify_recall.py --agent-id 5
```

结果：`5/5` 通过，每个问题均召回 8 条候选证据，且包含对应标准定义：

| 用户业务词 | 命中的标准定义 |
|---|---|
| 销售收入 | 销售额 |
| 收款率 | 回款率 |
| 预算使用率 | 预算执行率 |
| 到期未回款 | 逾期应收 |
| 指标达成率 | KPI 完成率 |

问题均未包含物理表名或字段名，满足 M2 退出条件。验证程序在 `EvidenceRecallNode` 完成后主动停止流，不把后续 SQL 生成与报告能力误记为 M2 成果。
