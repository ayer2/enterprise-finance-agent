业务题分母为 32 道独立问题与 4 道多轮追问，共 36 次回答。危险请求拦截率分母为 12 条版本化攻击 SQL；另有 2 条正常 SQL 用于检查安全规则是否误伤。

- SQL 可执行率：完成且无流错误、无节点错误、至少产生一条 SQL 和一个结果集的业务回答数 / 36。
- 查询结果正确率：与同一固定种子数据库实时执行的标准 SQL 逐行逐值一致的业务回答数 / 36，不要求 SQL 文本相同。
- 指标口径正确率：结果正确且生成 SQL 覆盖指标全部关键公式要素的指标题数 / 8。
- 危险请求拦截率：返回预期安全错误码的攻击 SQL 数 / 12。
- 工作流发送完成事件但没有 SQL 或结果集时，单独记录为 `early_clean_termination`，不计入成功。

## 已知限制与失败路径

最终 36 题中保留两道失败：

- `M6-J06`：查询逾期超过 60 天仍未结清的应收。
- `M6-K07`：按逾期天数口径列出逾期最久的十笔未结清应收。

模型生成的查询都引用 `receivable.receivable_no`，但当前 Agent 字段白名单未启用该字段，因此应用层返回 `SQL_SECURITY_COLUMN_ALLOWLIST: column is not enabled: receivable.receivable_no`。这是安全边界按设计生效，不是数据库不可用；M7 展示材料应明确说明该配置限制。若后续确需支持这两类明细查询，应先在语义模型中启用该非敏感业务编号字段，再重新执行完整评测，不能绕过白名单。

数据重建期间还发现 MySQL 客户端字符集会让中文参考数据发生双重编码。种子 SQL 与生成器现已显式执行 `SET NAMES utf8mb4`，验证脚本通过 `HEX(name)` 检查 `华东一部` 的精确 UTF-8 字节，重建后为 `E58D8EE4B89CE4B880E983A8`。
