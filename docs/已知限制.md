# 已知限制

## 当前产品边界

- 只使用合成数据，不连接真实 ERP、CRM、财务系统或生产身份目录。
- 只提供分析查询，不执行记账、付款、审批、修改数据等业务写操作。
- 默认 Compose 面向本地演示，不包含 HTTPS、统一登录、细粒度后台权限、限流、高可用、灾备和集中密钥托管。
- 页面中的 Agent API Key 管理不是已完成的外部接口鉴权方案；公开服务前需要在后端补充强制校验。
- 默认使用 SimpleVectorStore。Compose 提供持久卷，但不等同于生产级向量数据库的并发、备份和迁移能力。
- 默认部署不挂载 Docker Socket，因此不启用 Python 沙盒；当前企业财务 MVP 的验收范围是 SQL-only 分析。

## 模型与评测边界

- Chat 和 Embedding 依赖外部兼容服务，首次部署必须由使用者在本地页面输入并激活自己的 API Key。
- 模型结构化输出存在非确定性；服务启动、模型测试或 HTTP 200 均不能替代一次完整的问题→计划→SQL→结果→报告验收。
- M6 固定种子评测共 36 次业务回答。SQL 可执行率和结果正确率均为 94.44%，不是 100%。
- `M6-J06` 与 `M6-K07` 引用了当前字段白名单未启用的 `receivable.receivable_no`，被 `SQL_SECURITY_COLUMN_ALLOWLIST` 阻断。若要支持这两类应收明细，应显式评审并启用该非敏感业务编号字段，然后重新跑完整评测，不能绕过白名单。
- 评测数据、标准答案和指标仅适用于当前代码、题集指纹和固定种子版本，不应外推为真实企业准确率或生产 SLA。

## 数据与安全边界

- 部门范围通过合成请求上下文演示，不等同于与企业 IAM、SSO 或组织目录集成的生产 RBAC。
- 手机号、邮箱等字段为合成值，脱敏逻辑用于验证技术边界，不证明满足任何特定行业合规认证。
- Compose 将后端和数据库端口映射到宿主机以便本地验证；公开部署时应只暴露反向代理，并通过防火墙限制管理面和数据库。
- `.env`、模型 API Key、数据库密码、下载报告和本地运行日志不得提交到仓库或出现在公开截图中。
